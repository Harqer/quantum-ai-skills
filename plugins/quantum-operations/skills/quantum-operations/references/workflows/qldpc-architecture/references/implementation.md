# Quantum LDPC architecture: implementation reference

This reference turns a qLDPC family into an executable candidate. It separates algebraic code quality from syndrome extraction, decoder feasibility, hardware connectivity, logical operations, and whole-machine resources.

## 1. Required inputs

Capture:

~~~text
workload:
  logical_qubits
  required_logical_operations
  logical_measurements
  protected_rounds / algorithm schedule
  target_failure_budget

physical:
  one_qubit_error
  two_qubit_error
  measurement_error
  reset_error
  idle_error
  leakage/correlations/bias
  operation timings

connectivity:
  native coupling graph
  long_range_gate model
  movement/transport model
  teleportation/network model
  parallelism/crosstalk constraints

classical:
  decoder compute target
  memory/bandwidth
  syndrome-to-correction deadline
~~~

Keep every unavailable quantity explicit and carry it as an unresolved candidate field.

## 2. Candidate classes

Use finite instances whose matrices and protocols are available for engineering comparisons.

| Candidate class | Typical role | Required evidence before adoption |
| --- | --- | --- |
| Bivariate/generalized bicycle | finite high-rate memory and near-term qLDPC architecture | exact polynomials/matrices, syndrome schedule, circuit-level decoder, routing |
| Hypergraph product | general product-code studies, expander/single-shot variants | parent matrices, product construction, decoder validity domain, finite parameters |
| Lifted product / quantum Tanner | asymptotically good high-rate/high-distance families | concrete finite instance, parity checks, preparation, decoder and logical operations |
| Balanced/fiber-bundle/product variants | asymptotic construction and specialized finite candidates | explicit finite construction and executable protocol |
| Specialized self-dual / tricycle / single-shot families | logical Clifford, magic-state, or single-shot roles | gate/preparation protocol and circuit-level evidence for the selected instance |

Asymptotic rate or distance is architectural evidence. A physical-resource estimate uses the actual finite block chosen for execution.

## 3. CSS representation and invariants

For a CSS code, store binary matrices

~~~text
Hx : X-check parity matrix
Hz : Z-check parity matrix
~~~

with the commutation invariant

~~~text
Hx @ Hz.T == 0  (mod 2)
~~~

and

~~~text
n = number of data-qubit columns
k = n - rank_GF2(Hx) - rank_GF2(Hz)
~~~

Record row-weight and column-weight distributions separately. A qLDPC family keeps these weights bounded as block length grows; a concrete implementation also records the actual finite-instance weights.

Distance provenance uses one of:
- an exact proof/source for the selected instance;
- an exact solver/certificate;
- separately labeled lower and upper bounds;
- a heuristic search result explicitly labeled as a bound.

## 4. Bivariate-bicycle construction

For cyclic group orders `ell` and `m`, work over

~~~text
R = F2[x,y] / (x^ell - 1, y^m - 1).
~~~

Let commuting binary circulant matrices `A` and `B` be generated by two bivariate polynomials. Construct

~~~text
Hx = [ A | B ]
Hz = [ B^T | A^T ].
~~~

Because the circulants commute,

~~~text
Hx Hz^T = A B + B A = 0  (mod 2).
~~~

The current `qldpc` package exposes this construction directly:

~~~python
from sympy.abc import x, y
from qldpc import codes

code = codes.BBCode(
    {x: 12, y: 6},
    x**3 + y + y**2,
    y**3 + x + x**2,
)

assert code.dimension == 12
~~~

Use the package's current documentation before relying on additional methods. In particular, `get_distance_bound(...)` is documented as an upper-bound search and is not an exact-distance certificate.

## 5. Syndrome extraction

Build syndrome extraction from the actual Tanner graph.

For each check, store:
- ancilla preparation basis;
- ordered data/check interactions;
- measurement basis;
- idle locations;
- conflict-free interaction layer;
- hook/fault-propagation orientation;
- reset and leakage handling.

For every round compute:

~~~text
CNOT_or_entangling_layers
full_cycle_layers
ancilla_qubits
edges_executed
max_parallel_edges
routing_or_transport_time
cycle_time
detectors_produced
~~~

Keep entangling depth and full syndrome-cycle depth as distinct conventions.

For the bivariate-bicycle family in Bravyi et al., the reference implementation uses one check ancilla per check and an eight-round pipelined syndrome cycle around six data-check interactions per stabilizer. The paper/preprint reports a depth-7 entangling circuit convention; the implementation includes preparation/measurement in the complete repeated cycle. Preserve the source convention when comparing cycle depth.

Validate the circuit by propagating the stabilizer transformation and by circuit-level fault injection. The syndrome circuit is part of the code candidate; a parity-check matrix alone is insufficient for a hardware claim.

## 6. Decoder branch

### Code-capacity baseline

For a binary parity-check problem `H e = s (mod 2)`, current `ldpc` 2.1.0 documents BP+OSD as:

~~~python
from ldpc import BpOsdDecoder

decoder = BpOsdDecoder(
    H,
    error_rate=physical_error_rate,
    bp_method="product_sum",
    max_iter=max_iter,
    schedule="serial",
    osd_method="osd_cs",
    osd_order=2,
)

estimate = decoder.decode(syndrome)
~~~

BP+OSD is a robust finite-length baseline for many qLDPC families. Record BP method, schedule, iteration cap, OSD method/order, priors, convergence status, and latency.

For a more local/parallel post-processing path, current `ldpc` 2.1.0 documents BP+LSD:

~~~python
from ldpc.bplsd_decoder import BpLsdDecoder

decoder = BpLsdDecoder(
    H,
    error_rate=physical_error_rate,
    bp_method="product_sum",
    max_iter=max_iter,
    schedule="serial",
    osd_method="lsd_cs",
    osd_order=2,
)
~~~

### Repeated and circuit-level decoding

A fault-tolerant execution produces a space-time decoding problem. Build the detector/error-mechanism matrix from the complete repeated syndrome circuit and its noise model, then decode that circuit-level model. Keep X/Z-separated approximations, correlated models, and any hyperedge decomposition as named experimental variants.

Compare BP+OSD against decoder families justified for the selected instance, such as BP+LSD/localized statistics, ambiguity clustering, graph-augmentation/min-sum methods for correlated errors, beam search, Tanner-specific decoders, small-set-flip for expander assumptions, or another validated decoder.

For every decoder candidate report:

~~~text
logical_error_rate + confidence interval
shots / failures
mean latency
p99 latency
p99.9 latency
throughput
memory/bandwidth
convergence/restart/fallback rate
deadline misses
~~~

Pass live timing distributions into `real-time-qec-decoding`.

## 7. Hardware mapping

Convert the Tanner graph into a hardware interaction record:

~~~text
native_edges
long_range_edges
maximum_interaction_distance
interaction_distance_histogram
routing_layers
SWAP_count or movement/transport distance
teleportation/link demand
parallel interaction conflicts
cycle stretch from routing
extra routing/communication error
layout ancillas
~~~

A low check weight reduces the number of incident interactions; it does not imply 2D geometric locality. Candidate hardware mechanisms include reconfigurable atom movement, long-range Rydberg interactions, multilayer superconducting routing/couplers, modular links, and fusion/photonic constructions when the target platform supports them.

## 8. Logical computation record

Fill a complete logical ISA table for the workload:

~~~text
operation | mechanism | protected cycles | ancillas | measurements | byproducts | evidence
X/Z
H
S
CNOT/CZ
Pauli-product measurement
logical preparation
logical measurement
T / CCZ / arbitrary rotation
inter-block routing
~~~

Use proven code automorphisms or transversal gates where available for the selected code. Use dynamic syndrome circuits, code switching, generalized surgery, teleportation, or heterogeneous qLDPC/surface-code interfaces where they form the executable protocol. Universal computation additionally records non-Clifford state production/injection and routes its factory cost into `magic-state-factories`.

## 9. Fair surface-code comparison

Compare candidates at the same:
- logical qubit count;
- workload or protected-round count;
- total logical failure target;
- physical noise model;
- gate/measurement/reset timing;
- classical feed-forward policy.

Report separately:

~~~text
data qubits
syndrome/check ancillas
routing/communication ancillas
factory qubits
total peak physical qubits
syndrome-cycle time
decoder resources
logical operation cycles
wall-clock runtime
spacetime volume
failure-budget allocation
~~~

Encoding rate alone is not a resource estimate.

## 10. Acceptance criteria

A qLDPC candidate enters the Pareto frontier when all of the following are concrete:
- parity checks and commutation verified;
- code dimension verified and distance provenance recorded;
- check/variable weights measured;
- syndrome circuit and fault-propagation behavior specified;
- circuit-level logical-error evidence or an explicitly bounded substitute supplied;
- decoder accuracy and real-time service margin measured;
- physical routing/transport cost included;
- logical state preparation and readout defined;
- workload logical ISA complete, with each remaining unsupported operation surfaced;
- physical and classical resources compared against the same error budget and machine model as the baseline.
